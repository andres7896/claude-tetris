# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A playable classic Tetris built in vanilla JavaScript (ES6+) with HTML5 Canvas and CSS. No dependencies, no build step, no `package.json` — three files cooperate: `index.html`, `style.css`, `game.js`.

## Running the game

Open `index.html` directly in a browser, or serve it statically:

```bash
python3 -m http.server 8000
npx serve .
php -S localhost:8000
```

There is no bundled test suite, linter, or build/bundle process. Verify changes by opening the page in a browser and playing. For fast logic-only regression checks (no browser needed), a Node harness can load `game.js` into a `vm` context (stubbing `document`/canvas/`requestAnimationFrame`) and call its top-level functions directly — useful for exercising scoring, combos, hold/undo, and the challenge modes without manually placing pieces.

## Architecture

All game logic lives in `game.js` (single file, no modules). Key pieces:

- **Board model**: `board` is a `ROWS × COLS` matrix; each cell is `0` (empty) or a color index identifying what locked there: `1–7` tetrominoes, `8` = `WILD` (Tint comodín), `9–11` = pentomino pieces (`+`, `U`, `Y`), `12` = the post-Tetris reward single, `13` = the hollow-3×3 challenge piece, `14` = `GARBAGE` (basura / bloques fijos).
- **Pieces**: `PIECES` defines all spawnable shapes as square matrices (indices `8` and `14` are `null` — never spawned directly). `makePiece(type)` is the single factory (copies the shape, centers it at the top); `randomPiece()` calls it after rolling for a pentomino (`PENTO_CHANCE`) or hollow piece (`HOLLOW_CHANCE`), otherwise a plain tetromino. `queue` (array, kept refilled to ≥5 by `refillQueue()`) replaces the old single `next` slot; `queue[0]` is the on-deck piece. Power-ups (`randomPowerUp()`) and the Tetris reward (`makePiece(12)`) are inserted with `queue.unshift(...)` so they appear next without disturbing the rest of the queue.
- **Rotation**: `rotateCW()`/`rotateCCW()` transpose + reverse rows. `tryRotate()` picks CW or CCW (CCW only in `reverse` mode once `level >= REVERSE_START_LEVEL`), applies it, and on collision tries wall-kick offsets `[0, -1, 1, -2, 2]`; a successful rotation sets `lastMoveRotate = true` (cleared by any successful translation), which feeds T-spin detection.
- **Collision**: `collide(shape, ox, oy)` checks board bounds and overlap with locked cells (including `GARBAGE`); used by movement, rotation, ghost projection, and spawn (game-over check).
- **Lock/merge/clear cycle**: `lockPiece()` → (power piece: `activatePowerUp()`; normal piece: `detectTSpin()` then `merge()`) → `clearLinesAndScore(tspin)` (scans bottom-up, splices full rows, unshifts empty ones at top, applies combo/B2B/perfect-clear/T-spin scoring, updates lines/level/energy, and inserts power-up/reward pieces into `queue`) → `checkModeProgress()` (challenge-mode win check) → `spawn()` (shifts `queue`, refills it, re-enables hold, checks game-over via `collide`, snapshots state for Undo).
- **Game loop**: `loop(ts)` runs via `requestAnimationFrame`, accumulates elapsed time in `dropAccum`, and advances the piece down one row (or locks it) once `dropAccum >= dropInterval` (doubled while `slowRemaining > 0`, suspended while `freezeRemaining > 0`). **It bails out immediately (no `requestAnimationFrame` reschedule) whenever `gameOver`, `paused`, or `abilityMenuOpen` is true** — this is what stops the game for good instead of silently continuing to spawn/lock pieces behind the overlay.
- **Scoring/leveling**: `LINE_SCORES = [0, 100, 300, 500, 800]` (or `TSPIN_SCORES` for a T-spin clear) × `level`, × `combo` (consecutive clearing locks) if `combo > 1`, ×`B2B_MULTIPLIER` when a Tetris/T-spin clear follows another one back-to-back; a fully empty board after clearing adds `PERFECT_CLEAR_BONUS * level`. Hard drop adds 2 pts/cell, soft drop 1 pt/row (not multiplied). Level increases every 10 lines; `dropInterval = max(100, 1000 - (level-1)*90)` ms.
- **Ghost piece**: `ghostY()` projects the current piece straight down to its landing row; drawn at `globalAlpha = 0.2`.
- **Power-ups**: every `POWERUP_EVERY` lines cleared, `clearLinesAndScore()` inserts one via `queue.unshift(randomPowerUp())` (a 1×1 piece tagged `power: 'bomb' | 'ray' | 'tint' | 'gravity' | 'freeze'`) instead of a normal tetromino. It moves/rotates/drops like any piece but never `merge()`s into the board — `lockPiece()` routes it to `activatePowerUp()` instead, which mutates `board` directly (3×3 clear, row+column clear, recolor to `WILD` cells, per-column compaction, or setting `freezeRemaining`) and scores destroyed cells via `BLOCK_BONUS * level`. `isRowFull()` (used by `clearLinesAndScore()`) treats a row as complete if at most one cell is empty and the row contains a `WILD` cell, so Tint-created wildcards can complete near-full rows. `freezeRemaining` (ms, ticked down in `loop()`) suspends only the automatic `dropAccum` advance, not player input. Transient visuals (flash cells, stacked effect-name banners, the invisible-mode reveal fade) live in the `effects` array, decremented each frame and drawn by `drawEffects()`/`draw()`.
- **Hold**: `holdPiece()` (keys `C`/`Shift`) stores the current piece type in `hold` and pulls the next queue piece, or swaps with whatever is already held; `canHold` blocks a second use until `spawn()` re-enables it (rendered dimmed via the `.locked` class on `#hold-canvas`). Power-up pieces can't be held.
- **Loadable abilities**: `energy` (0–100, `+ENERGY_PER_LINE` per line cleared) gates `E` (`openAbilityMenu()`, pauses the loop and shows `#ability-menu`); `useAbility(1–5)` grants a 30s next-5 reveal (`revealRemaining`, drawn on `#queue-canvas`), a random-type swap of `current`, a 10s slowdown (`slowRemaining`, doubles the effective drop interval), an Undo (`performUndo()` restores the snapshot `takeSnapshot()` captured at the last `spawn()`), or unlocks Hold again (`canHold = true`) — then resets `energy` to 0.
- **Challenge modes**: `mode` (`'classic' | 'sprint' | 'garbage' | 'fixed' | 'invisible' | 'reverse'`), chosen from the `#mode-menu` overlay and passed to `init(mode)`. `checkModeProgress()` (after every lock) and per-frame checks in `loop()` call `endGame(true)`/`endGame(false)` for each mode's win/lose condition (40 lines within 2:00 for `sprint`; survive 2:00 of `addGarbageRow()` pushes for `garbage`; clear all `initFixedBoard()`-seeded `GARBAGE` cells for `fixed`; 20 lines while locked cells stay unrendered except a brief reveal fade for `invisible`; 30 lines with CCW rotation active past `REVERSE_START_LEVEL` for `reverse`). `objectiveLabel()` renders the live objective/timer text.
- **Records**: `records` (`{ top, bestCombo, maxLines }`) is persisted in `localStorage` under `tetris.records` (last typed name under `tetris.playerName`). `endGame()` calls `updateBests()` (best combo tracked per run in `maxComboRun`, max lines in one game) and, if `qualifiesForTop(score)`, sets `pendingRecord` so the game-over overlay shows a name form; `commitPendingRecord()` inserts it (top `TOP_N` = 5, any mode) and runs on form submit, `init()` and `showModeMenu()` so restarting never loses it. `renderRecords()` (called from `setOverlayView` for the mode menu and game over, not pause/ability) draws the list, highlighting the pending/just-saved row; `resetRecords()` wipes everything after a `confirm`. The `keydown` handler ignores events targeting an `<input>` so typing a name doesn't trigger mute/pause/drop.
- **Rendering**: `draw()` clears and redraws the grid, locked board (skipped per-cell in `invisible` mode unless a `reveal` effect is active), ghost piece, current piece, effects, hold, and the ability-3 queue preview each frame onto `#board`/`#hold-canvas`/`#queue-canvas`; `drawNext()` renders `queue[0]` on `#next-canvas`.
- **Sound**: `sfx(kind, comboLevel)` synthesizes short square-wave beeps via the Web Audio API (`audioCtx`, created lazily on first use) — no audio files. `muted` (toggled with `M`) short-circuits it.
- **Pause menu**: `P`/`Escape` call `togglePause()` → `pauseGame()`/`resumeGame()` (no-op while `gameOver`, the ability menu, or the mode menu is showing — tracked by `overlayView`, set in `setOverlayView()`). Pausing shows the `#pause-menu` overlay view: Reanudar, Reiniciar (`init(mode)`), Ver controles (`#controls-menu` view; `Escape` goes back to the pause menu), a `−/+` **start-level** selector (`startLevel`, 1–`MAX_START_LEVEL`) and Menú principal. `init()` copies `startLevel` into `baseLevel`, and `clearLinesAndScore()` computes `level = baseLevel + floor(lines/10)` — so changing the selector mid-game only affects the next game. Game keys are ignored while `paused` and for `RESUME_INPUT_LOCK_MS` after `resumeGame()` (`inputLockUntil`), preventing accidental moves on return.
- **Input**: a single `keydown` listener routes by state — the ability menu (if open) only accepts `1`–`5`/`Escape`; otherwise `P`/`Escape` toggle pause (`Escape` first steps back out of the controls view), and while playing (not paused, past the resume input lock), arrows/`X`/`Space`/`C`/`Shift`/`E` drive movement, rotation, soft/hard drop, hold, and opening the ability menu.

### Tunable constants (top of `game.js`)

`COLS`, `ROWS`, `BLOCK` (cell size in px), `COLORS`/`PIECES` (indices `1–14`, see Board model above), `LINE_SCORES`/`TSPIN_SCORES`, `B2B_MULTIPLIER`, `PERFECT_CLEAR_BONUS`, `ENERGY_PER_LINE`, `PENTO_CHANCE`/`HOLLOW_CHANCE` (spawn odds for the pentomino/hollow pieces), initial `dropInterval`, `POWERUP_EVERY` (lines between power-ups), `FREEZE_MS`/`SLOW_MS`/`REVEAL_MS` (ability/power-up durations), `BLOCK_BONUS` (points per cell destroyed by Bomb/Ray), and the per-mode constants (`SPRINT_TIME`, `SPRINT_TARGET_LINES`, `GARBAGE_INTERVAL`, `SURVIVAL_TIME`, `FIXED_ROWS`, `INVISIBLE_TARGET_LINES`, `REVERSE_TARGET_LINES`, `REVERSE_START_LEVEL`), `MAX_START_LEVEL` (cap of the pause-menu start-level selector), `RESUME_INPUT_LOCK_MS` (input lock after resuming). If `COLS`/`ROWS`/`BLOCK` change, update the `#board` canvas `width`/`height` in `index.html` to match (`COLS × BLOCK` by `ROWS × BLOCK`).
